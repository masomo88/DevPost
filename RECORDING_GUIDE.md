# ShelfLoop demo recording guide

The [Arbiter overview](https://arbiter-hacks-v1.devpost.com/) requires a working demo video, 2–3 minutes maximum, uploaded to YouTube or Vimeo and linked in the Devpost entry. **No video has been recorded or uploaded yet.** Use the timed shots and spoken text in [DEMO_SCRIPT.md](DEMO_SCRIPT.md).

## Before recording

1. Open the [live demo](https://masomo88.github.io/DevPost/) and [public code](https://github.com/masomo88/DevPost/) in separate browser tabs. Close tabs and notifications that show private information.
2. In the demo, click **Load example**. This replaces the current browser inventory. If you want to keep existing data, first click **Export CSV** and save it separately.
3. Check the date shown in **Add food**. The form defaults to three days from the current date. Use **Zucchini**, **275 g**, and that default date in the demonstration.
4. Rehearse once with a timer. The narration describes a proposed impact measurement, not observed savings. Show the optional local AI only if a real local model is running and its output has been checked. The hosted demo does not use Ollama.

## Capture on Windows

Microsoft's [Snipping Tool instructions](https://support.microsoft.com/en-gb/windows/apps/use-snipping-tool-to-capture-screenshots) describe video capture: press **Windows + Shift + R**, select the browser area, start recording, then stop and save the video. Make the browser large enough for labels and numbers to remain legible. A microphone narration can be recorded while demonstrating or added in a video editor afterward; check the saved file for audible sound, readable text, and correct length before uploading.

Follow this sequence: dashboard and problem; add zucchini and reload; priority list and grounded recipe; mark the new item **Used** and show the journal; briefly show the public repository; close with the pilot measurement plan. Keep the screen focused on actual interactions and avoid implying that example data are real results. Do not show private account information.

## Final check

- Video shows the app working and runs 2–3 minutes.
- The spoken claims match the on-screen state. The 275 g journal entry is self-reported use, not measured waste prevention.
- Demo and source links in the description work without sign-in.
- The upload link is publicly viewable and is ready for the Devpost entry.

Recording or upload must be completed by the entrant or with access to their chosen account. The source repository and live demo are already public; this guide does not replace the required video.
